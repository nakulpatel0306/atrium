Sandboxing agents on macOS.

Agents are fast, which is the point and also the risk. The bottleneck I want is a human yes, and I'd rather enforce that in how Atrium is built than in a prompt that asks nicely.

NP Nakul Patel / November 6, 2026 / 5 min read

Atrium runs AI agents on my Mac: Claude, Codex and Gemini. I type what I want, an agent does the work, and the result waits in a list called Needs you until I approve it. I call that rule draft and wait.

A rule in a prompt is a request. An agent reading a web page or a repo can be talked out of it by text it finds there. So the rules that matter most are enforced by the operating system, around the agent, where nothing it reads can change them. This note is about how that works on macOS.

Two sandboxes, one set of rules

In plain terms

A sandbox is a set of limits the operating system enforces on a program: which files it can read or write, which network addresses it can reach, which other programs it can start. The program can't lift them, however it's asked.

Atrium uses two, because the agents come from different places.

Claude runs through the Claude Code command-line tool, which has its own sandbox. Atrium turns it on for every run and pins its settings with a --settings file it writes per run.

Codex and Gemini run inside a sandbox Atrium builds itself, using a tool that ships with macOS.

In plain terms

Seatbelt is the sandbox built into macOS. The sandbox-exec command starts a program under a Seatbelt profile, a short list of allow and deny rules written in a Lisp-like language.

The two are configured differently, but they enforce the same list. Both block credentials, loopback (so agents can't call Atrium's own API), Apple Events, open and Shortcuts.

What's blocked, and why

  • CredentialsKeys, tokens and anything that looks like a .env file.

    SSH keys, cloud credentials, the GitHub CLI's login, the Keychain files, shell history, browser and mail data, Messages, Contacts, and Atrium's own data folder. Files named like .env are blocked anywhere, for reading and for writing, so an agent can't rename one into something readable.

  • LoopbackAtrium's own API.

    The engine listens on 127.0.0.1, port 7420, and nowhere else. If an agent could reach that address, it could forge a request and approve its own drafts. So agents can't open connections to localhost at all. They only need the internet.

  • Apple Events and openStarting or scripting other apps.

    Apple Events are how one Mac app tells another what to do. The open command asks macOS to launch an app. Either way the new app runs outside the sandbox, which would be a clean escape.

  • ShortcutsThe Shortcuts app and its relatives.

    Shortcuts runs its work in its own background service, outside the sandbox and without an Apple Event to block. So the shortcuts, osascript and automator commands are denied, and so are the system services behind Shortcuts, so even a copied binary can't reach them.

  • GitHubPushing and creating repos.

    No GitHub CLI, no SSH to port 22, no local sockets (which is how SSH agents hand out keys), and the GitHub token variables are stripped from the agent's environment.

Claude's settings

For Claude, the core of it is a block of settings Atrium writes for each run:

src/engine/agents/claude.ts · sandboxSettings, trimmed 
sandbox: {
  enabled: true,
  failIfUnavailable: true,
  allowUnsandboxedCommands: false,
  allowAppleEvents: false,
  filesystem: { denyRead: ["~/.ssh", "~/.aws", "~/.gnupg", "~/.config/gh", "~/Library/Keychains", /* … */] },
  network: { allowedDomains: ["registry.npmjs.org"], allowLocalBinding: false, allowAllUnixSockets: false },
}

Two details matter more than they look. Settings passed with --settings outrank a repo's own .claude settings and mine, and with allowUnsandboxedCommands off, a cloned repo can't add exceptions for itself. And failIfUnavailable means that if the sandbox can't start, Claude doesn't run. It never quietly runs unconfined.

There's one gap the sandbox doesn't cover: it wraps the shell commands Claude runs, not Claude's own built-in file tools. So Atrium also passes a deny list of tool patterns, like Read(~/.ssh/**), Bash(open *), Bash(*osascript*) and Bash(git push*). The OS sandbox is the wall; the deny list covers the door the wall doesn't reach.

The Seatbelt profile

Codex and Gemini get a profile Atrium generates per run. A few of its lines:

src/engine/agents/seatbelt.ts · generated profile, trimmed 
(version 1)
(allow default)
(deny lsopen)
(deny appleevent-send)
(deny process-exec (literal "/usr/bin/osascript"))
(deny process-exec (literal "/usr/bin/shortcuts"))
(deny network-outbound (remote tcp "*:22"))
(deny network-outbound (remote unix-socket))
(deny network-outbound (remote ip "localhost:*"))

I want to be upfront about the second line. This profile allows everything by default and then denies specific things. The agents need the network to reach their provider and need to read ordinary files to work, so a deny-by-default profile wouldn't run them. What the profile does guarantee is that secrets can't be read and writes stay inside the folders it lists.

Two lessons came from writing it:

  • Paths must be resolved first. Seatbelt matches real paths, so /var has to be written as /private/var. A rule with the unresolved path doesn't error. It just silently never matches.
  • Shared temp folders aren't private. Each run gets its own temp folder, pointed to by TMPDIR, and it's deleted when the run ends.

If sandbox-exec can't start, the run doesn't happen, and the agent is paused with a plain message: “Atrium couldn't start the sandbox for Codex; this agent is paused for safety.”

Codex and Gemini's file reads aren't fenced as tightly as Claude's, so they never run in a private space. There, Atrium says plainly that only Claude works in it.

The engine does what leaves the Mac

All of that keeps agents from doing things. The other half is who does them instead.

Anything that leaves the Mac, like a push, a new GitHub repo or a text message, is done by the engine, never by an agent, and only after I say yes. An agent that wants to text a friend writes a draft. Atrium shows it in Needs you exactly as it will be sent, and only Atrium sends it, after I press Send. If an agent claims it did something only the engine can do, the card says it couldn't, instead of pretending.

Card and account numbers are cut down to their last four digits before anything is stored. Data that was never stored can't leak.

Each rule turns a failure that would have been silent into one I can see. That's most of what safety means to me here.

One of the holes I closed today was Shortcuts. It's a good reminder that a sandbox isn't finished when it first works. It's finished when I've stopped finding ways around it.
