Picking the right agent for the job.

Atrium can run three different agents. Most of the time I leave it on Auto, but the rules behind Auto are worth knowing, because they're about safety as much as quality.

NP Nakul Patel / November 8, 2026 / 4 min read

In a chat window, the model is whatever tab you opened. In Atrium, every task has an agent, and there are three to choose from: Claude, through the Claude Code command-line tool on my subscription; Codex; and Gemini, through a command-line tool called agy. Each task can name one, or say Auto and let Atrium decide when it runs.

Which agent may do which job isn't a matter of taste. It comes down to what each one can be safely boxed in to do.

Who can do what

Each ✕ has a reason, and Atrium says it on the task instead of failing quietly:

  • Private spaces“This space is private, so only Claude works in it.”

    Claude runs inside Claude Code's own sandbox, with Atrium's settings pinned and a deny list on its file tools. Codex and Gemini run in a sandbox Atrium builds, but their file reads aren't fenced as tightly. So spaces holding texts, money or my portfolio never go to them.

  • .env files“This repo has .env files Codex could read. Use Claude for this task.”

    A .env file usually holds keys and passwords. Claude is blocked from reading them. In a repo that has them, Codex and Gemini are kept out entirely, for reviews too.

  • Gemini in a repo“Gemini only reviews code; pick Claude or Codex for repo work.”

    Its search tool can't be turned off, and it can't run tests headless, so it doesn't edit repos. Reviewing a diff only means reading, which it does fine.

What Auto does

Auto is decided at the moment a task starts, not when I create it, and the choice is recorded on that run. The rule is short:

  1. Reviews go to Codex, then Gemini.

    If either is installed, signed in and allowed in the space, it takes the review. That keeps Claude free for the work itself, and makes it more likely the reviewer isn't the agent that wrote the code.

  2. Most work goes to Claude.

    Code changes, private spaces and anything else default to Claude.

  3. Except when Claude's window is running low.

    Once half of Claude's five-hour usage window is used, Claude tasks wait so I have some left when I sit down. On Auto, non-code work in a non-private space goes to Codex or Gemini instead of waiting.

If I care which agent does a task, I pick it. A named agent is never swapped for another. If it can't run, the task waits and says why: for a usage limit, when the agent picks up again, and “Pick another agent to run it sooner.”

Where each one works

In a general space, Claude works directly in the space's folder. Codex and Gemini work in a fresh temporary folder instead, and Atrium copies the files they leave into the space's runs folder when they finish, so their work is kept without them ever having the space's other files in reach.

A second agent for code

A model reviewing its own work mostly agrees with itself. A different model, with no memory of the reasoning, reads the code as it is. So a code space can name a reviewer, and every finished change gets a second opinion before it reaches me.

The details are what make it trustworthy:

  • The reviewer changes nothing. The diff is in its prompt, and its instructions say not to create or change any file. It ends with a verdict line: approve or changes.
  • One fix round, then stop. If it asks for changes, the original agent makes them on the same branch, with the review in its instructions. There's no second review, so the loop can't go back and forth on its own.
  • It never blocks me. I can approve while the review is still running. If it arrives after I've decided, it's noted in the task's thread but not added to a decision I already made, and any pending fix is skipped.
  • The agents talk where I can read it. The review and any fix notes go into the task's thread, so I can see exactly what one agent told the other.

I use the same idea when I build Atrium itself, with a fresh agent reviewing each plan's work. A second set of eyes catches what the first one was sure about.

Why not just one model?

One model for everything is simpler, and for a single chat it's the right call. For work that runs unattended, three things make several worth it: some jobs need a stricter sandbox than some agents can offer, a usage limit on one shouldn't stop all my work, and a reviewer is more useful when it isn't the author. Atrium makes those calls the same way every time, and writes down why.

Auto isn't “whichever model is best today”. It's a short list of rules about what each agent can be trusted with.
