Get Atrium

How agents are kept in.

Atrium lets AI agents change code on your Mac. The rules that matter most are enforced around each agent, by macOS and by Atrium's engine, where nothing an agent reads can talk them away. Here's what they cover, where they stop, and how to report a hole.

Updated November 18, 2026

The sandbox around every agent

Claude runs inside Claude Code's own sandbox, with settings Atrium passes on every run: the sandbox is required and no command may run outside it, no settings file from your repo or your home folder is loaded, hooks are off, and only the built-in tools Atrium allows are there at all. Codex and Gemini run inside a macOS sandbox profile (sandbox-exec) that Atrium writes for every run.

What agents can't read

  • Every agent: SSH, AWS and GPG keys, the GitHub CLI's login, Messages and Contacts, and Atrium's own database, transcripts and log, and every space's folder but the task's own.
  • Every agent, any .env file, anywhere: every name that starts or ends with .env, in any case, and everything inside a folder named that way.
  • Codex and Gemini, also: the other credential files (.netrc, .npmrc, .pypirc, git credentials, Docker, Kubernetes, Google Cloud and Azure logins, password stores), shell history, browser data, Mail, Claude's folder, each other's sign-in folder, and your Keychain files, except the one login keychain file Antigravity signs in through. Claude's shell can't read the Keychain files either.

What agents can't reach or run

  • Atrium's API: loopback is blocked, so an agent can't approve its own work.
  • Your other apps: no Apple Events, open, osascript, Shortcuts or Automator.
  • GitHub: no gh, no SSH, no SSH agent, and no git push or git clone from Claude. The GitHub tokens in the environment are removed before any agent starts.
  • The Keychain command, security.

What agents can't change

No agent can write the repo's node_modules or .venv: Atrium's checks run tools from those, so only the engine installs into them. Codex and Gemini can write only inside the task's folder, their own state and a temp folder of the run's own, and never the repo's .git or its agent settings in .claude and .agents. Claude's file tools can't edit .git or .claude either.

Private spaces

A private space only ever uses Claude. Its file tools are fenced to the space's own folder, it gets no shell unless it's a private repo's test commands, and Downloads, Desktop, Documents and bank exports (CSV, OFX, PDF and the like) are closed to it.

Only Atrium pushes, and only after your yes

Agents never push or create repos, and have no GitHub login to do it with. The engine does, with your own git identity and GitHub login, and only after you said yes: a push is refused unless the yes on it is yours, not a rule's.

Rules can approve a repeated kind of result for you, but a few things always wait for you, whatever a rule says:

  • pushing a branch, and merging to main (any work not on its own atrium/ branch);
  • deleting files;
  • touching secrets: .env files, keys and credential files;
  • deploy settings such as CI workflows and Dockerfiles;
  • creating a GitHub repo, spending money, and removing a clone.

Every approval a rule makes is logged and can be undone. And an agent's own word never counts: Atrium runs your checks itself, in a checkout of their own, under a sandbox profile of their own, with the commands taken from the commit the task started on.

What this doesn't cover

  • Agents are online. Each CLI has to reach its maker, so the sandbox doesn't cut off the internet, and what an agent can read can be sent there. Claude's shell commands may reach only the npm registry; the Codex and Gemini processes keep their network, and Antigravity's server-side web search can't be switched off.
  • Prompt injection. An agent reading a repo, an issue or a web page can be talked into a bad change inside its sandbox. That's why nothing leaves your Mac without your yes, and why the reviewer and you read the diff.
  • Checks are evidence, not proof. A change can still weaken a test without skipping it. The loop docs list every known way a change can alter what its checks mean, and which stay open.
  • Codex's subagents can't be switched off completely; they run inside the same sandbox as the writer.
  • The sandboxes are macOS's and Claude Code's. A flaw in either is a flaw here. Atrium runs as you, so it can't protect anything from programs you run outside it.

Reporting a vulnerability

Please report it privately, through GitHub: open a private security advisory on the repo. Don't open a public issue for it. Say what you did, what happened, and the commit you were on. Only the latest main is supported.

Fixes land as public commits, and the advisory is published once the fix is in. The same steps are in the repo's SECURITY.md. What Atrium keeps and sends is on the privacy page.
