One request, start to finish.

It's easier to judge a tool by following one real request all the way through than by reading its feature list. Here's one, step by step.

NP Nakul Patel / November 8, 2026 / 4 min read

I've written about the pieces separately: spaces, the queue and draft and wait. This note follows one small, everyday request through all of them, so you can see how they fit.

The request: my friends Sam and Priya and I are hiking on Saturday, and I want to lock in the plan. In a chat window, that's “write me a text”, then copy it, open Messages, find Sam, paste, send, and do it again for Priya. Here's what it is in Atrium.

The seven steps

Step by step

1. The ask

I type into the Ask box: the command bar in the dashboard, or the box that's always at the bottom of the terminal app: “Text Sam to lock in Saturday's hike.” No context to paste. That's the whole request.

2. Understanding it

Claude reads the request first, with only read-only tools. Its job here is just to decide what kind of thing I asked for: a new space with tasks, a new code project, or a text to someone. It sees “text Sam” and answers with a message request: who it's to, and what it's about. It's told never to make a task that sends something, and it couldn't anyway.

3. A task in the right space

All texts live in one space called Messages, so my sent history is in one place. It's a private space, which means only Claude works there. Atrium adds a task, “Draft a text to Sam”, marked light so it runs even on battery.

4. The draft

Claude runs inside its sandbox, with instructions to write the text short, warm and in my voice. It ends its reply with a small block holding who it's for and the words, then its outcome line. Because drafting isn't sending, the honest outcome is “partly done: drafted a text to Sam. It sends only when you press Send.”

The agent never sees or picks a phone number. The block only carries a name and the text; anything else in it is ignored.

5. Needs you

The engine turns that block into a card. It looks Sam up in my Contacts to fill in the number, but only once a lookup I started myself has worked, so the macOS permission prompt only ever appears while I'm at the Mac. If there's no match or several, the card asks me to pick or type the number.

6. My yes

I read it. If I want different words, Edit opens the draft, and the confirm step shows my edited version before it goes. Then Send. That press is the only thing that can send a text. Rules can't do it, the agent can't do it, and a second click or a second app finds the send already taken and does nothing.

7. Sent and logged

The engine hands the text to the Messages app, over iMessage or SMS. The activity feed records “Sent via Messages to Sam (+1 555 014 2290). Atrium can't confirm delivery.” It says that because it really can't, and the task is marked done. If Messages fails, the card comes back with the reason, so the next try is again my own Send. If Atrium was stopped mid-send, the card says to check Messages before sending again, rather than risking a double text.

Then I do the same for Priya: a second ask, a second card, a second Send. Each text is its own draft with its own yes.

The same shape for a code fix

A bug fix in a code space follows the same seven beats with different actors. I ask, “fix the crash when the list is empty”. The task goes to the space's agent, which works on a branch of its own, atrium/<taskId>, inside its sandbox, and never on top of my uncommitted changes. The engine commits what it left. If the space has a reviewer, a second agent reads the diff and either approves or asks for one round of fixes.

The card then shows the commits and files changed, the agent's summary, the review and the honest outcome. I approve, and it ends the way every code task does: “Branch atrium/tsk_… is on your machine. Push it when you're ready.” The push, if I want one, is another yes.

What changed compared to a chat window

  • No context to carry in.

    The request was one line. The space and its rules supplied the rest.

  • No result to carry out.

    The draft became a ready-to-send card, with the number already filled in from my own Contacts.

  • The risky step stayed mine.

    The agent did the writing. Sending, the one step that can't be undone, waited for me and happened through the engine.

  • There's a record.

    The ask, the draft, my Send and the result are all in the Messages space's history, not in a chat I'll never scroll back to.

The agent did the part I'd rather not. I did the part only I should. Nothing in between was copy and paste.
