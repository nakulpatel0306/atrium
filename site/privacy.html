Get Atrium

Privacy, on your Mac.

Atrium is open-source software that runs on your Mac. There's no Atrium account, no Atrium server and no Atrium cloud. This page says what the app keeps and where, what leaves your Mac, how to delete all of it, and what this website does.

Updated November 18, 2026

What the app keeps, and where

Everything Atrium keeps is a file on your Mac. Run atrium data to see the folders and their sizes.

  • Its data folder, ~/Library/Application Support/Atrium: the database atrium.db (spaces, tasks, approvals, rules, settings and token counts), transcripts/ (what each agent said and did), the engine's log, and the sample repo Get started copies in if you try it. Each transcript stops at 5 MB, and once they add up to 200 MB the oldest are deleted first.
  • General spaces keep their files in ~/Atrium, a plain folder you can open in Finder. It's outside Documents and Desktop, so iCloud doesn't copy it off your Mac.
  • Code spaces work in your own repo. Each task's changes go on a branch named atrium/<taskId>, and Atrium won't start one over changes you haven't committed. A repo you point it at on GitHub is cloned into your projects folder. Files you attach to a task are copied into an Attachments folder in the space's folder.
  • Checks run in a temporary checkout in the system's temp folder, deleted as soon as they finish.
  • Claude Code's own files. Between turns of one task, Claude Code keeps the writer's session in its own session files, so the next turn can pick up where it left off. Private spaces never keep one.

Who can reach it

The engine listens on 127.0.0.1 only, so nothing else on your network can connect to it. It also turns away a web page in your browser: every request must name 127.0.0.1 or localhost as its host, a change is accepted only from Atrium's own page, and a read that says it comes from another site is refused. The agents' sandboxes block loopback, so an agent can't call it either.

What leaves your Mac

What the agent CLIs send their makers

Atrium doesn't talk to any AI service itself. It starts the agent CLIs you've installed (Claude Code, Codex, and Antigravity's agy for Gemini) as programs of their own, signed in with your own accounts. What you ask, and the code and files an agent reads to do it, go to that agent's maker under its own terms and privacy policy. Atrium doesn't change what they collect:

  • Claude Code, from Anthropic: Anthropic's privacy policy and how Claude Code uses your data.
  • Codex, from OpenAI: OpenAI's privacy policy.
  • Gemini through Antigravity, from Google: Google's privacy policy and Antigravity's terms.

One task can reach more than one maker

Each step of a task goes to whichever agent runs it, and they aren't always the same one:

  • Briefs, scouts, walkthroughs and the hunk explanations you ask for always run on Claude.
  • The writer is Claude unless you pick another agent for the task, or, for work in a general space, Claude's five-hour window is past the reserve you set.
  • The review of a code task, with Review with left on Auto, goes to another maker's CLI when one is installed and allowed in the space, so the diff and the brief go there too.

To keep a space's work with Claude alone, set its Review with to Claude (or Off) and don't pick another writer. Its Learning setting at Off stops the walkthroughs too. A space marked private only ever uses Claude, whatever its settings say.

Checking the agents are ready

To show whether each agent CLI is installed and signed in, Atrium asks it: when Get started or atrium doctor runs, and every ten minutes while Atrium is running (claude --version, codex login status, agy models). A CLI may ask its maker to answer. Get started and atrium doctor also run gh auth status, which asks GitHub whether you're signed in.

GitHub, when you ask

Beyond that sign-in check, Atrium uses git and the GitHub CLI, signed in as you, only for things you start: cloning or fetching a repo you pointed a space at, creating a new repo, and pushing a branch and opening its pull request. A push and a new repo each wait for your yes. Before deleting a clone, it fetches once to check that everything in it is on GitHub.

Nothing else

No telemetry, no analytics, no crash reports and no update checks. Atrium never phones home: updating it is a git pull you run yourself.

Deleting it

  • One space or task: delete it in the app, typing its name to confirm. The folders it made go to the Trash.
  • Data from older versions (mail, texting, money and investing, which Atrium no longer has): Remove old data on Home or in Settings → Data, or atrium data remove-old. It shows exactly what will go, including sign-in tokens those features left in your login Keychain, and removes nothing until you confirm.
  • Everything: run atrium uninstall. It stops the running engine and removes its login item, ~/Library/LaunchAgents/com.atrium.engine.plist, but deletes no data. If you installed the Mac app, atrium app uninstall quits it and removes ~/Applications/Atrium.app. Then delete ~/Library/Application Support/Atrium and ~/Atrium.

Even then, some things stay until you delete them yourself:

  • Your repos, their atrium/ branches, and the clones in your projects folder.
  • The writer sessions Claude Code kept for Atrium's tasks, which sit with your own Claude Code sessions under ~/.claude/projects/, in the folder named after each repo's path.
  • The Mac app's web data, under ~/Library/WebKit/com.atrium.app.
  • Whatever Claude Code, Codex and agy keep under their own settings, such as your sign-in and history.

This website

  • Hosting. These pages are served by GitHub Pages. GitHub logs every visitor's IP address for security, signed in to GitHub or not, under the GitHub Privacy Statement.
  • Nothing from anywhere else. Every font, script and image the pages load is served from this site, fonts included (Inter Tight and Geist Mono, under the SIL Open Font License). No trackers, no embeds. Links to GitHub and other sites load nothing until you click them.
  • No cookies, no analytics. The one thing stored is your theme choice, under atrium.theme in this browser's local storage. It never leaves your browser, and choosing Auto removes it.
  • The demo on the home page runs in the page on sample data. Nothing you type there is saved or sent.

Questions and changes

Ask in an issue on GitHub. Every change to this page is in the repo's history. How agents are kept away from your keys and files is on the security page.
