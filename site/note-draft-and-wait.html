Draft and wait: an assistant that acts needs a yes.

Assistants tend to come in two kinds: ones that can't do anything, and ones that do things without asking. Atrium sits in between on purpose.

NP Nakul Patel / November 7, 2026 / 4 min read

A plain chatbot can't act. It writes an answer, and you carry it into the world yourself: paste the code, send the email, rename the files. Safe, but you're doing the last and most tedious step every time.

An agent with tools can act. It edits files, runs commands, maybe sends things. That saves the tedious step, but now mistakes happen in the real world, often while you're looking elsewhere, and a permission prompt every thirty seconds trains you to click “allow” without reading.

Atrium's rule is in the middle, and it's the one rule everything else is built around. I call it draft and wait: agents do the work, but nothing gets sent or kept until I say yes.

One list for everything that needs a person

Every finished result becomes a card in Needs you. A code change waits there as a branch. A text waits as a draft with a Send button. A new GitHub repo waits as a plan of what would be created. The agent's work is real and finished; it just hasn't taken effect.

Each card opens to the detail: the agent's summary, the files it changed, the full transcript of its run. And each card has the same few choices.

Send back, with a note

Approve and no are obvious. Send back is the one that replaces the chat back-and-forth.

When I send a result back, I can add a note: “Use the existing date helper instead of a new one.” The task goes back in the queue, and my note is added to its instructions as “Feedback: …”. The next run starts with the original task, the space's goal, the files as they are, and my feedback. Like everything else in the queue, it waits its turn, as I described in Hand it off and walk away. For a code task it carries on from the same branch, so the earlier work is still there.

That's the same correction I'd type into a chat, except I don't have to stay and watch the retry. It's back in Needs you when it's done.

Honest outcomes

A yes is only as good as what I'm saying yes to. If an agent says “done” when it only did half, I'll approve the half without knowing.

So every agent is told to end with exactly one line saying how it went, and Atrium reads that line, not the agent's tone:

src/engine/outcome.ts · what every agent is told 
Your very last line must be exactly one of:
OUTCOME: done
OUTCOME: partial - <one plain sentence saying what's left>
OUTCOME: couldnt - <one plain sentence saying why>
Say done only if you did everything the task title asks. Drafting something is not sending it.
  • done
  • partly donesays what's left
  • couldn'tsays why
  • can't tellno clear line

The label is the first thing on the card, above the summary. A few details keep it honest:

  • Only the last line counts. An agent quoting the instructions halfway through its reply hasn't reported anything.
  • “Done, but…” isn't done. “Done” takes no explanation. An agent that writes “done - though nothing was sent” is hedging, and the card says Atrium can't tell.
  • Some things only the engine can do. If a task asks to send a text or create a repo and the agent claims it's done, Atrium knows that's impossible, because agents can't do either. The card says it couldn't, instead of believing it.
  • Accepting less is recorded as such. If I approve something the agent said it couldn't finish, the activity feed says “Accepted anyway”, not “Approved”.

Earning the right to skip the wait

Asking about everything forever would be its own kind of failure. If I approve the same kind of thing again and again without changing a word, the asking is just friction.

So Atrium watches for that, carefully. When I've approved five results of the same kind in a row in one space, within two weeks, all of them as they were, with no note, no send-back and no review asking for changes, it suggests a rule. I can say yes, not now, or never.

The kinds a rule can cover are deliberately few and narrow:

  • Docs changes in a code space: Markdown in the docs/ folder or a README or CHANGELOG, either up to 50 lines or 51 to 200, from one named agent. Not code, not tests, and not anything a docs tool would run or that tells an agent what to do.
  • Text answers with no files from one named agent.

And a rule has limits of its own. It can only ever approve, never send back or reject. It expires after 60 days. It approves at most 10 results per space per day, and after that they wait for me. In a space with a reviewer, it only acts after the review said approve with no fixes needed. Any automatic approval can be undone, which puts the result back in Needs you and switches the rule off, because a rule I had to undo is a rule I don't trust.

What always asks

Some actions never get a rule, however many times I've approved them. They're on a fixed always-ask list, and the rule system has no words for them. Among them:

  • sending a text
  • pushing
  • creating a repo
  • merging to main
  • deploying
  • deleting
  • spending money
  • secrets

Every text Atrium sends as me goes out only after I press Send on that exact text. If I edit the draft first, the edited words are what's sent, and the card shows them before I confirm.

An assistant that can act is only useful if I can trust what it did. Draft and wait is how I get to trust it without watching it.
